# 공통 편집 엔진 추출 구현 기록

설계와 후속 웹 개발의 범위는 [웹 편집기 설계](web-editor-design.md)를 따른다. 이 문서는 `feat/shared-editor-engine`에서 만든 소비 경계와 검증 결과를 기록한다.

## 소스와 소비 단위

| 단위              | 위치                                           | 기존 앱의 실제 사용                                                                      |
| ----------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Rust 공통 엔진    | `src-tauri/crates/editor-engine`               | 기존 모델·상태 모듈이 공통 정의를 재노출하고, 저장 트랜잭션이 공통 변경 준비·확정을 호출 |
| TypeScript 편집기 | `packages/editor`의 `@dmnote/editor` workspace | 메인 Grid·도구 모음·속성 패널·다이얼로그, 오버레이 표면 및 화면별 API 설치 진입점        |
| IPC shim          | `packages/ipc-shim`의 `@dmnote/ipc-shim`       | OBS 어댑터가 공통 요청·콜백·이벤트 처리를 사용                                           |

TypeScript 공통 구현·타입·자산과 관련 테스트는 `packages/editor/src`에 둔다. 루트 `src`에는 데스크톱 창 진입점, 설정·업데이트 화면, OBS 연결 등 앱 전용 코드를 남긴다. 편집 UI·store·플러그인 런타임의 상호 의존을 유지하면서 공개 진입점에서 필요한 코드와 자산을 묶는다. 데스크톱 창 생성·메뉴·업데이트 화면까지 외부 소비자가 복사하는 방식이 아니다. 실제 배포 산출물은 `packages/editor/dist`, `packages/ipc-shim/dist`이며 생성 파일은 커밋하지 않는다.

공개 진입점에서 사용하는 실제 의존성 경로를 기준으로 소스를 이동했으며, 공통 패키지 선언이 앱 소스에 의존하면 빌드 검사가 실패한다. 앱 개발에서는 동일 소스에 연결하는 workspace 별칭을 사용해 기존 store와 런타임 인스턴스를 유지한다. 외부 소비 검증에서는 별칭을 사용하지 않고 `npm pack` 결과만 설치한다. 메인 화면의 개별 import 경계를 유지하기 위해 `grid`, `toolbar`, `panel-host`, `dialogs` 진입점을 제공한다. 전체 `editor` 진입점도 외부 조립용으로 제공한다.

## 책임과 확정 순서

Rust 공통 엔진은 모델, 편집 검증·정규화·전이, 변경 준비와 확정 결과, 히스토리 데이터와 계획, 프리셋 데이터 처리, 저장 데이터의 이식 가능한 마이그레이션·복구 판단을 소유한다. 데스크톱 호스트는 파일 I/O, 자산 경로 해석·설치, mutex와 admission, writer와 복구 파일, 이벤트 전송을 소유한다.

기존 앱의 저장 경계는 유지한다. 공통 엔진에서 다음 상태와 히스토리 계획을 준비하고, `commit_locked`가 writer 완료 후 메모리와 store revision을 공개한 다음, 공통 확정 로직이 히스토리와 이벤트 결과를 만든다. 공통 엔진은 디스크 저장 성공을 임의로 가정하지 않는다.

WASM의 `EditorSession`은 마이그레이션과 자산 복원이 끝난 상태를 받아 `prepare → 호스트 저장 → confirm` 또는 `discard`를 제공한다. 준비 중에는 다음 변경을 차단하고, mutation 재전송·revision 검사는 데스크톱과 같은 공통 함수를 사용한다. 이 JSON 호출 경계는 WASM 실행 가능성을 확인하는 최소 연결이다. SharedWorker 세션 등록·재시작, IndexedDB 트랜잭션, 모든 네이티브 커맨드의 웹 호스트 구현까지 포함하지 않는다.

프리셋의 포함 필드와 JSON에 자산을 묶는 기존 규칙을 유지한다. 플러그인 저장 데이터를 새로 프리셋에 포함하지 않는다. `dmn.*` 공개 API의 의미, OBS 권한 목록과 WebSocket·미디어 주소 처리도 유지한다.

## 패키지 연결 계약

편집기와 shim의 구체적인 공개 진입점·초기화·해제 계약은 [편집기 README](../packages/editor/README.md), [shim README](../packages/ipc-shim/README.md)에 둔다. Rust API와 WASM 빌드는 [엔진 README](../src-tauri/crates/editor-engine/README.md)를 따른다.

호스트를 설치한 뒤 편집기 runtime과 화면을 불러온다. 기존 모듈은 import 시점에 창 역할을 읽거나 전역 API를 등록하므로, 웹 소비자가 호스트 준비 전에 화면을 정적으로 import하면 안 된다. 메인과 오버레이는 각각의 문서에서 별도 런타임을 갖고 호스트 이벤트로 연결한다. DOM 플러그인을 Worker로 옮기지 않는다.

`npm run build:packages`는 JS·CSS·자산과 TypeScript 선언을 생성한다. 선언 파일의 앱 소스 별칭을 상대 경로로 변환하며, 타입 검사를 건너뛰지 않는다. React는 peer dependency로 두어 소비 프로젝트와 같은 인스턴스를 사용한다.

## 검증 방법

- 설계 커밋 `69bb58c`를 별도 임시 소스에서 실행해 변경 전 테스트·타입·빌드 기준선을 확보한다.
- 기존 Rust 테스트를 공통 crate 또는 호스트의 원래 책임에 맞게 보존한다. 소스 경로를 읽는 프론트 계약 테스트는 정의가 이동한 경로로 수정하고 기대값은 유지한다.
- 공통 변경 로직의 데스크톱 저장 연결과 세션 결과를 비교하고, 기존 편집·히스토리·프리셋·플러그인·저장 실패·복구 테스트를 실행한다.
- 실제 Tauri JS API와 Channel을 통해 shim의 요청·이벤트·콜백 순서 및 해제를 검사한다. OBS 어댑터 통합 테스트도 실행한다.
- 외부 임시 프로젝트에 tarball을 설치하고 `skipLibCheck: false` 선언 검사, 소스 별칭 없는 Vite 빌드, 실제 패키지의 렌더링과 편집 coordinator 왕복을 검사한다.
- `wasm32-unknown-unknown` 빌드 결과를 wasm-bindgen으로 연결해 실제 Node WASM에서 준비·취소·확정·재전송·충돌·프리셋 디코딩·마이그레이션을 실행한다.
- CI의 Rust 검사를 workspace 전체로 확대해 이동한 공통 crate 테스트가 누락되지 않도록 한다. 외부 패키지 검사와 WASM 실행도 CI에 포함한다.

## 검증 결과

기존 Rust 테스트 함수의 이동 전후 목록을 비교해 누락이 없음을 확인했다. 네이티브 store와 공통 세션의 결과·이벤트·실패 의미 비교 테스트, 공통 프리셋 계획 6개 및 실제 Tauri API/OBS shim 계약 테스트가 포함된다. 프론트의 기존 `SoundTrimModal` hook 의존성 경고와 앱 번들 크기 경고는 기준선에도 있었다.

Windows 실행과 ASIO, 실제 WebView에서의 전체 수동 편집, 실제 OBS 앱 연결은 이 환경에서 수행하지 않았다. Windows 검사는 기존 CI에 유지하고 공통 crate까지 확장했다. 이 결과는 실행한 자동 회귀 검사와 코드·소비 경계 비교에 대한 확인이며, 웹 제품 완성이나 모든 플랫폼의 수동 동작 확인을 의미하지 않는다.

## 후속 범위

SharedWorker와 IndexedDB 호스트, 브라우저 파일 선택·다운로드·자산 URL 관리, main/overlay iframe 구성, CSS 중계 Worker와 웹 제품 개발은 기존 설계대로 후속 작업이다. 패키지 게시와 버전 정책, 별도 저장소 이전 여부도 별도 작업이다. 현재 패키지 경계는 소스를 DmNote 안에서 관리하면서 외부에서 소비할 수 있는 형태를 검증한다.

## 디렉터리 이동 검토

사용자 요청에 따라 `src`를 패키지 루트로 삼던 최초 구현을 `packages/editor`로 정리했다. manifest와 산출물뿐 아니라 실제 공통 구현·타입·자산·관련 테스트를 함께 이동했다. 공개 진입점의 TypeScript 의존성을 기준으로 분류하고, 앱 전용 화면과 호스트 연결은 루트에 유지했다.

기준 커밋과 이동 후 코드를 독립적으로 비교했다. 공통 생산 코드 610개의 import 경로를 제외한 transpile 결과와 비-import 문자열·템플릿은 동일했고, 관련 자산·JSON·스타일·선언 41개는 바이트가 동일했다. 선언 생성은 TypeScript AST의 실제 모듈 참조만 변환하며, 공통 선언이 앱 소스에 의존하면 실패한다. 내부 import 2,927건의 이동 후 대상도 기대 경로와 일치했다. 테스트의 파일 탐색 범위도 앱과 패키지를 모두 포함하도록 유지한다.
